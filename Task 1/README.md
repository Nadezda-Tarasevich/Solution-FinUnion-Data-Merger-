### README: Архитектура данных FinUnion Group (объединение с RetailBank)

#### Описание

Данный проект содержит  анализ данных двух организаций с выделением ключевых бизнес-сущностей и описанными связями между ними, классифицированными данными по критичности и типы хранилищ.



#### Документы проекта



README.md - содержит краткий путеводитель по документам проекта

entities.md

logical-data-model.pdf

data-classification.md

storage-strategy.md

reference-model.md



#### Содержание документов



##### 1\. entities.md - содержит описание ключевых бизнес-сущностей, которые участвуют в объединении FinUnion и RetailBank.

* Клиент (Customer)	
* Договор (Agreement)	
* Счёт (Account)	
* Карта (Card)	
* Транзакция (Transaction)	
* Платёж (Payment)
* Продукт (Product)
* Обращение (Interaction)	
* Сегмент клиента (Segment)
* Сотрудник (Employee)



##### 2\. logical-data-model.pdf- ER-диаграмма (PlantUML)

В файле logical-data-model.pdf представлена логическая схема связей между ключевыми сущностями.

Основные связи:

* Клиент → Счёт (обязательная, 1:N) — владелец счёта
* Клиент → Договор (1:N) — сторона договора
* Договор → Счёт (1:N) — счета по договору
* Договор → Продукт (N:1) — используемый тариф
* Счёт → Транзакция (1:N) — движение средств
* Счёт → Платёж (1:N) — платежи отправителя
* Карта → Транзакция (1:N) — операции по карте
* Обращение → Клиент (N:1) — инициатор обращения
* Клиент → Сотрудник (N:1) — закреплённый менеджер

##### 3\. data-classification.md- Классификация данных и ИБ

Таблица классификации данных с указанием:

* Категории данных (ПДн, БД, КД, ОД, платёжные данные)
* Уровня критичности (Критичная / Высокая / Средняя / Низкая)
* Влияния на ИБ
* Средств защиты (шифрование, маскирование, RBAC, аудит, DLP)

Приоритеты защиты:

1.Критично: карточные данные (PAN, CVV2) — токенизация, PCI DSS

2.Высокий: ПДн и банковская тайна — шифрование, RBAC

3.Средний: справочники и сегменты — RBAC

4\.Плановый: DLP-системы

##### 4\.storage-strategy.md - Типы хранилищ для целевого решения

Документ описывает типы хранилищ для разных групп данных с обоснованием выбора: 

* OLTP: Операционные данные: Клиенты, Счета, Договоры, Транзакции
* MDM: Золотые записи клиентов, справочники
* DWH: Регламентированная отчётность, BI-витрины
* Data Lakehouse: Исторические транзакции, события
* Объектное хранилище: Документы, записи звонков, архивы
* Графовая БД: Связи клиентов для AML
* Поисковый движок: Поиск по обращениям и клиентам



##### 5\. reference-model.md- Сопоставление с BIAN

Матрица сопоставления бизнес-сущностей с сервисными доменами BIAN с объяснением, как референсная модель помогает:

•Унифицировать терминологию после слияния

•Определить границы владения данными

•Найти пересечения между системами FinUnion и RetailBank

•Подготовить целевые домены данных и Data Products
