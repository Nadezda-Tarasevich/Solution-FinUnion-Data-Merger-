### Таблица классификации данных FinUnion Group (объединение с RetailBank)

|сущность|категория данных|критичность|влияние на ИБ|средства защиты|
|-|-|-|-|-|
|Клиент (Customer)|ПДн (персональные данные) + БД (банковская тайна/данные)|высокая|Утечка: нарушение 152-ФЗ, 395-1-ФЗ (ст. 26 — банковская тайна), штрафы, уголовная ответственность. Риск репутационного ущерба и отзыва лицензии ЦБ.|Шифрование: AES-256 для ПДн в хранилище, TLS 1.3 для передачи. Маскирование: динамическое маскирование для некритичных интерфейсов (контакт-центр). <br />RBAC: ролевая модель (доступ только по принципу необходимости). Аудит: логирование всех запросов к ПДн (кто, когда, какие данные). DLP (data loss prevention): предотвращение утечек через email, USB, мессенджеры.|
|Договор (Agreement)|БД (банковская тайна) + КД (коммерческая тайна/данные)|высокая|Утечка: раскрытие условий кредитования/обслуживания конкурентам, нарушение ст. 26 395-1-ФЗ. Риск потери конкурентных преимуществ, судебных исков от клиентов.|Шифрование: AES-256 для хранения. RBAC: доступ только сотрудникам с ролью “Договоры” и “Риск-менеджмент”. <br />Аудит: журнал изменений (кто изменил сумму/ставку, когда). <br />Срок хранения: 10 лет после закрытия договора (согласно ЦБ).|
|Счёт (Account)|БД (банковская тайна) + ОД (операционные данные)|высокая|Утечка: раскрытие остатков и движения средств клиента. Нарушение ст. 26 395-1-ФЗ. <br />Риск: целевые атаки на крупных клиентов (социальная инженерия).|Шифрование: шифрование остатков в DWH. Маскирование: маскирование номера счёта в отчётах для некритичных ролей. <br />RBAC: строгое разграничение (кассир видит только последние 4 цифры). <br />Аудит: логирование любых запросов остатков не владельцам счёта.|
|Карта (Card)|ПДн (персональные данные) + БД (банковская тайна/данные)+ платежные данные|Критичная|Утечка: раскрытие PAN, CVV, ПИН-кода. Нарушение PCI DSS, 152-ФЗ, 395-1-ФЗ. <br />Риск: финансовые потери от фрода (до 100% ответственности банка), отзыв лицензии платёжной системы (Visa, Mastercard, МИР).|Токенизация: замена PAN на токен в CRM и DWH. <br />Шифрование: AES-256 для хранения PAN (только в карточном процессинге). Запрет хранения CVV2/PIN: хранение только хэша PIN. <br />Segregation: изоляция карточного процессинга в отдельный сегмент сети. <br />PCI DSS: ежегодный аудит, сканирование уязвимостей. <br />DLP: блокировка отправки PAN по email.|
|Транзакция (Transaction)<br />|БД (банковская тайна) + ОД (операционные данные)|Высокая|Утечка: раскрытие платёжного поведения клиента. Нарушение банковской тайны.<br /> Риск: профилирование клиентов для мошеннических схем.|Шифрование: шифрование канала (TLS) при передаче в DWH. Маскирование: маскирование суммы и RRN для некритичных отчётов. <br />RBAC: доступ только для фрод-мониторинга и отчётности. <br />Аудит: логирование массовых выгрузок транзакций.|
|Платёж (Payment)<br />|БД (банковская тайна) + ОД (операционные данные)|Высокая|Утечка: раскрытие платёжных инструкций (кто кому перевёл). Нарушение 115-ФЗ, ст. 26 395-1-ФЗ. Риск: блокировка корреспондентских счетов ЦБ.|Шифрование: TLS для передачи платежей. <br />RBAC: строгий доступ для РКО и финмониторинга. <br />Аудит: полное логирование изменений статуса платежа (кто отменил/изменил). <br />Срок хранения: 5 лет (согласно 115-ФЗ).|
|Продукт (Product)<br />|КД (коммерческая тайна)<br />|Средняя|Утечка: раскрытие тарифов и условий продуктов до официального запуска. <br />Риск: потеря конкурентного преимущества, копирование тарифов конкурентами.|RBAC: доступ только для продуктовых менеджеров и маркетинга. <br />Срок хранения: бессрочно (архивирование старых версий). Аудит: фиксация изменений тарифов и дат ввода.|
|Обращение (Interaction)<br />|ПДн (персональные данные) + БД (банковская тайна/данные)|Высокая|Утечка: раскрытие истории обращений, жалоб, претензий. Нарушение 152-ФЗ. <br />Риск: репутационный ущерб, судебные иски от клиентов (особенно по жалобам с записью разговора).|Шифрование: шифрование записей звонков и чатов. <br />Маскирование: скрытие ПДн в расшифровках для аналитиков. <br />RBAC: доступ только для контакт-центра и риск-менеджмента. <br />Аудит: логирование прослушивания записей. <br />Срок хранения: 3 года (согласно ЦБ).|
|Сегмент клиента (Segment)<br />|ПДн (персональные данные, косвенно)|Низкая (без привязки к конкретному клиенту)/Средняя (с привязкой)|Утечка правил: низкий риск. <br />Утечка списка клиентов сегмента:<br />раскрытие коммерческой информации (VIP-клиенты).|RBAC: доступ к полному списку клиентов сегмента только для маркетинга. <br />Маскирование: агрегированные данные без ПДн — открытый доступ. Аудит: логирование выгрузок списков клиентов.|
|Сотрудник (Employee)<br />|ПДн (персональные данные сотрудника)|Средняя|Утечка: раскрытие личных данных сотрудников (паспорт, адрес, зарплата). Нарушение 152-ФЗ, ТК РФ. <br />Риск: утечка реквизитов для фишинговых атак на банк.|Шифрование: шифрование ПДн сотрудников. <br />RBAC: доступ только для HR и ИБ. Аудит: логирование изменений в профиле сотрудника. <br />DLP: защита от копирования базы сотрудников.|
