# Анализ ключевых бизнес-сущностей компании FinUnion Group



Анализ ключевых бизнес-сущностей для объединения FinUnion (FU) и RetailBank (RB), с учётом банковской специфики

|Бизнес-сущность|Описание|Основные атрибуты|Связи|Система-источник|Критерий включения|Проблемы качества|
|-|-|-|-|-|-|-|
|Клиент (Customer)|Физическое или юридическое лицо, вступающее в договорные отношения с банком. Является центральной сущностью, вокруг которой выстраиваются все продукты, взаимодействия и отчётность. Без единого, очищенного профиля клиента невозможны кросс-продажи, качественное обслуживание и корректная регуляторная отчётность.|Идентификаторы: ИНН, СНИЛС (для физ. лиц), паспорт (серия/номер), ОГРН/ОГРНИП (для юр. лиц/ИП), внешние ID из FU CRM и RB CRM. Описательные: полное наименование (для юр. лиц) / ФИО (для физ. лиц), дата рождения (для физ. лиц), тип клиента (физ. лицо / юр. лицо / ИП), статус (активен / заблокирован / закрыт). <br />Контакты: мобильный телефон, email, адрес регистрации/проживания/юридический.|Договор, Счёт, Карта, Обращение, Сегмент|FU CRM, RB CRM, FU Core, RB Core|Центральная сущность для единого профиля клиента, кросс-продаж, AML-проверок, отчётности. Без неё невозможна консолидация данных.|Дубли: один и тот же клиент заведён в FU и RB с разными ID (например, 12345 в FU и ABC-678 в RB). Пропуски: у части юр. лиц отсутствует ИНН (старые записи), у физ. лиц — телефон или email. Разные форматы: паспорт «4001 123456» (FU) vs «4001-123456» (RB), дата рождения «15.03.1985» vs «1985-03-15». Устаревшие данные: адреса и телефоны не обновлялись 3+ года, клиент мог переехать.|
|Договор (Agreement)|Юридический документ, фиксирующий отношения между клиентом и банком. Включает все типы: кредитный, карточный, ДБО, вкладной, счётный. Кредитный договор является подтипом Договора. Договор — это «обёртка», которая связывает клиента с продуктом и набором счетов/карт.|Идентификаторы: номер договора, внешние ID из FU Core и RB Core. Классификаторы: тип (кредитный / карточный / ДБО / вкладной / счётный), статус (действует / закрыт / расторгнут), продукт (ссылка на Продукт). Условия (для кредитных/вкладных): сумма, процентная ставка, срок, дата начала, дата окончания, валюта, график платежей. Стороны: клиент (обязательно), банк.|Клиент, Счёт, Карта, Продукт, Обращение|FU Core, RB Core, FU CRM, RB CRM|Юридическая основа всех продуктов. Позволяет отслеживать полную продуктовую историю клиента, обязателен для отчётности и аудита.|Дубли: один и тот же договор (например, кредитный на сумму 1 млн руб.) заведён в FU и RB с разными номерами — № 12345-FU и № ABC-678-RB. Пропуски: у части договоров отсутствует ссылка на продукт (не указано, какой тариф применяется). <br />Разные форматы: тип договора «Кредитный» (FU) vs «Договор займа» (RB) — одно и то же. Устаревшие данные: закрытые договоры не помечены статусом «закрыт», продолжают учитываться в отчётности.|
|Счёт (Account)|Банковский счёт для учёта денежных средств клиента. Всегда имеет прямого владельца — клиента. Счёт открывается, как правило, в рамках Договора, но владелец (клиент) — обязательный атрибут.|Идентификаторы: номер счёта (20 знаков), внешние ID из FU Core и RB Core. Классификаторы: тип (расчётный / ссудный / вкладной / транзитный), валюта, статус (активен / заблокирован / закрыт). <br />Финансовые: остаток, дата открытия, дата закрытия. Владелец: ссылка на Клиента (обязательно). Договор: ссылка на Договор (обязательно для ссудных и вкладных, опционально для расчётных).|Клиент, Договор, Транзакция, Карта, платежи|FU Core, RB Core|Основа для всех денежных потоков и расчёта остатков. Без прямой связи с клиентом невозможна корректная отчётность по клиентским средствам.|Дубли: один и тот же счёт заведён в обеих АБС (при миграции). Пропуски: у 5% счетов в RB Core нет ссылки на клиента (сиротские счета, нет владельца). Разные форматы: тип «Расчётный» (FU) vs «Текущий» (RB). Устаревшие данные: счета со статусом «активен» не имеют движения 5+ лет.|
|Карта (Card)|Платёжная карта (дебетовая, кредитная, предоплаченная). Привязывается к Счёту (для дебетовых) или является продуктом по Договору (для кредитных). Критична для ИБ.|Идентификаторы: PAN (в токенизированном/хэшированном виде), внешний ID карты в FU Cards и RB Cards. Классификаторы: тип (Visa / Mir / Mastercard), статус (активна / заблокирована / утеряна / перевыпущена), продукт/тариф (ссылка на Продукт). Финансовые: кредитный лимит (для кредитных карт), дата выпуска, дата окончания срока действия. <br />Связи: счёт (основной для дебетовых), договор (для кредитных).|Счёт, Транзакция, Договор|FU Cards, RB Cards|Ключевой продукт розничного бизнеса, чувствителен к ИБ|Разные статусы: В FU “активна” = 1, в RB “активна” = “A”.<br />Утерянные связи карта-счёт: В RB Cards некоторые карты не имеют актуальной привязки к счёту в RB Core.<br />Дубли PAN: Одна карта может быть выпущена в обеих системах (ошибка интеграции).<br />Устаревшие данные: карты, заблокированные 2 года назад, в системе всё ещё «активны».|
|Транзакция (Transaction)|Факт движения денежных средств по Счёту или Карте. Базовая единица для расчёта остатков, комиссий, выручки и фрод-мониторинга.|Идентификаторы: ID транзакции, RRN. Временные: дата и время авторизации, дата клиринга.<br />Финансовые: сумма, валюта, комиссия. Классификаторы: тип (пополнение / списание / перевод / оплата), статус (успешно / отклонено / возврат), MCC-код (для карт). Связи: счёт или карта (обязательно).|Счёт, Карта, Платёж|FU Core, RB Core, FU Cards, RB Cards<br />|Основа для операционной отчётности, выручки, фрод-мониторинга и МСФО.|Дубли: одна транзакция может быть загружена в обе DWH. <br />Пропуски: в RB DWH нет транзакций старше 3 лет. <br />Разные форматы: дата «2025-03-15 14:30:00» (FU) vs «15.03.2025 14:30» (RB). <br />Устаревшие данные: статусы не обновляются после клиринга (остаются «в обработке»).|
|Платёж (Payment)|Инструкция на проведение денежного перевода (платёжное поручение, платёжное требование, автоплатёж, перевод). Может исполняться одной или несколькими Транзакциями.|Идентификаторы: ID платежа, номер поручения. Временные: дата создания, дата исполнения. Финансовые: сумма, валюта. Классификаторы: тип (срочный / обычный / регулярный / автоплатёж), статус (исполнен / ожидает / отменён). Реквизиты: отправитель (счёт / карта), получатель (счёт / карта / реквизиты юрлица), назначение платежа.|Счёт, Транзакция|FU Core (РКО), RB Core (РКО), FU Cards (переводы)|Важен для финансового мониторинга и отчётности по платежам.|Дубли: автоплатежи заведены в обеих системах и выполняются дважды. <br />Пропуски: у 20% платежей в RB Core пустое назначение платежа. <br />Разные форматы: тип «Срочный платёж» (FU) vs «Платёж срочный» (RB). <br />Устаревшие данные: платежи со статусом «ожидает» не обновляются годами.|
|Продукт (Product)|Банковский продукт (карта/вклад/кредит/ДБО) с набором характеристик, тарифов и условий. Является справочной сущностью-каталогом, на которую ссылаются договоры.|Идентификаторы: код продукта, название. Классификаторы: категория (розница / МСБ), тип (карта / вклад / кредит / ДБО), сегмент (массовый / VIP / пенсионный). <br />Условия: процентная ставка, комиссии, лимиты, срок, требования к клиенту. Срок действия: дата запуска/остановки продаж.| Договор|FU Core, RB Core, FU CRM|Необходим для унификации продуктовой линейки, снижения стоимости обслуживания и единой отчётности.|Дубли: один продукт (карта с бесплатным обслуживанием) назван «Золотая карта» (FU) и «Карта Премиум» (RB). Пропуски: у части продуктов не указаны комиссии. Разные форматы: ставка «15%» (FU) vs «0.15» (RB). Устаревшие данные: продукты, снятые с продаж 2 года назад, всё ещё активны.|
|Обращение (Interaction)|Любое взаимодействие с клиентом: запрос, жалоба, консультация, заявка на продукт, рекламация.|ID обращения, номер в CRM. Временные: дата создания, дата закрытия. Классификаторы: канал (офис / чат / звонок / веб), тип (консультация / претензия / заявка / жалоба), статус (открыто / в работе / закрыто), тема (потеря карты / вопрос по тарифу). Контекст: клиент (обязательно), договор/счёт/карта (опционально). Результат: решение, комментарий, оценка.|Клиент, Договор, Счёт, Карта (опционально, для контекста)|FU CRM, RB CRM, контакт-центры<br />|Позволяет строить единую историю обслуживания клиента, не терять обращения при слиянии компаний.|Дубли: одна жалоба заведена в FU и RB . Пропуски: в RB CRM нет обращений старше 1 года. <br />Разные форматы: канал «chat» (FU) vs «online-chat» (RB). <br />Устаревшие данные: обращения со статусом «открыто» не закрыты 6+ месяцев.|
|Сегмент клиента (Customer Segment)|Группировка клиентов по общим признакам (доход, поведение, регион, отрасль). Используется для маркетинга, скоринга, отчётности.|Идентификаторы: код сегмента, название («VIP», «Массовый», «Пенсионер»). Классификаторы: категория (розница / МСБ). Правила: критерии включения (депозит > 1 млн ИЛИ доход > 500 тыс.), дата актуальности. |Клиент|FU CRM, RB CRM, FU DWH<br />|Ключевой для маркетинга, скоринга и отчётности по клиентским группам.|Дубли: один клиент — «VIP» в FU и «Золотой» в RB. Пропуски: у части клиентов сегмент не определён. Разные форматы: «Mass Affluent» (FU) vs «Состоятельный» (RB). Устаревшие данные: сегменты не пересчитывались 2 года.|
|Сотрудник / Пользователь системы (Employee)|Сотрудник банка, который взаимодействует с системами и клиентами. Важен для отчётности по нагрузке, аудита действий и разграничения доступа. Является «внутренним клиентом» для CRM и системы управления задачами.|Идентификаторы: табельный номер, логин. Описательные: ФИО, должность, подразделение, регион. Ролевые: роль (менеджер / риск-менеджер / финансовый аналитик / ИТ-специалист), уровень доступа, статус (активен / уволен / в отпуске). Аутентификация: email, номер телефона.|Обращение. Клиент|FU CRM (справочник сотрудников), RB CRM, HR-система (Active Directory)|Необходим для аудита действий, отчётности по нагрузке и разграничения доступа. Без него невозможно отследить, кто и когда работал с клиентом.|Дубли: один сотрудник заведён в FU CRM и RB CRM с разными ID (после перехода). Пропуски: у некоторых сотрудников не указано подразделение. Устаревшие данные: уволенные сотрудники остаются в системе с активным статусом, что создаёт риски ИБ.|
