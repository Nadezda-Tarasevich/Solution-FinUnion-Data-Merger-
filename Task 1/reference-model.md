### Сопоставление бизнес-сущностей компании FinUnion Group с областями BIAN

|сущность|область BIAN (Service Domain)|обоснование|
|-|-|-|
|Клиент (Customer)<br />|Party Reference Data Directory<br />|Единый справочник всех сторон (физических и юридических лиц). Он хранит атрибуты (ФИО, ИНН, паспорт, адрес) и обеспечивает идентификацию. При слиянии FU и RB это ключевой домен для построения MDM (золотой записи клиента).|
|Договор (Agreement)<br />|Product Access|Домен, управляющий доступом клиента к продукту (договор). Договор — это юридическая «обёртка», которая связывает клиента с продуктом|
|Счёт (Account)<br />|Current Account / Savings Account / Loan Account<br />|Детализированные типы счетов: текущий, сберегательный, ссудный. Для унификации важно определить, какой тип счёта используется в какой АБС (FU Core vs RB Core) и привести к единой модели.|
|Карта (Card)<br />|Card Management<br />|Управление жизненным циклом карты: выпуск, блокировка, перевыпуск, тарифы. BIAN определяет единые статусы (активна, заблокирована, утеряна) — помогает устранить расхождения между FU Cards и RB Cards.|
|Транзакция (Transaction)<br />|Transaction Processing (Authorization + Clearing + Settlement)<br />|Обработка операций (авторизация, клиринг, расчёт) с разделением авторизации и клиринга, что помогает построить единую модель транзакций (в FU Core и RB Core могут быть разные стадии).|
|Платёж (Payment)<br />|Payment Execution<br />|Исполнение платежей (платёжные поручения, переводы)с единым жизненным циклом платежа (создание, валютный контроль, отправка в платёжную систему).|
|Продукт (Product)<br />|Product Catalog + Product Design<br />|Product Catalog — каталог продуктов (справочник), Product Design — дизайн продукта (ставки, лимиты, условия). Оба домена нужны для унификации продуктовой линейки FU и RB.|
|Сегмент клиента (Segment)<br />|Segment Management<br />|Управление сегментацией клиентов. Помогает устранить дублирование сегментов (VIP в FU vs Золотой в RB) и унифицировать правила отнесения клиентов к сегментам|
|Обращение (Interaction)<br />|Customer Relationship Management<br />|Домен для управления взаимодействиями с клиентом (звонки, чаты, визиты, жалобы). |
|Сотрудник (Employee)<br />|Employee Management (расширение BIAN, нестандартный домен)|BIAN не выделяет Employee как сервисный домен. Для банка этот домен критичен (аудит, RBAC, управление доступом). Вводится как расширение BIAN для целей слияния.|
