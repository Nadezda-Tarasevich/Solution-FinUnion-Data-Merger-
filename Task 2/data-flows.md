### Основные потоки данных FinUnion Group (промежуточное состояние, 3 месяца)



|Источник|Приёмник|Передаваемые сущности|Тип действия|Режим обмена|Обоснование|
|:-:|:-:|:-:|:-:|:-:|:-:|
|Клиент|FU CRM, RB CRM|Клиент (создание/обновление), Обращение|Create/Update|Синхронный (онлайн)|Клиент взаимодействует с банком через CRM. Данные должны быть актуальны сразу после ввода.|
|FU CRM, RB CRM|FU Core, RB Core|Клиент, Договор (новые), Счёт (на открытие)|Create/Update|Синхронный (онлайн)|После создания клиента в CRM договор и счёт создаются в АБС в реальном времени для проведения операций.|
|FU CRM, RB CRM|MDM (синхронный кэш)|Клиент (ФИО, ИНН, паспорт, телефон, email)|Create/Enrich|Синхронный (gRPC/REST, < 3 сек)| MDM возвращает pre-golden\_id синхронно через gRPC/REST на основе точного совпадения ИНН или паспорта. Если клиент найден — возвращается существующий golden\_id. Если нет — создаётся временный pre-golden\_id.|
|FU CRM, RB CRM|ESB|Клиент (события создания/изменения)|Create/Update|Асинхронный (Kafka)|События о клиентах отправляются в ESB для асинхронного матчинга в MDM. Этот поток запускает глубокий матчинг, который позднее подтверждает или объединяет pre-golden\_id.|
|FU Core, RB Core|FU Cards, RB Cards|Счёт (для выпуска карты), Договор (для кредитной карты)|Create/Update|Синхронный (онлайн)|Для выпуска карты нужен актуальный счёт в АБС. Карта привязывается к счёту в момент выпуска.|
|FU Core, RB Core|FU Loans, RB Loans|Ссудный счёт, Договор кредита, Лимит|Create/Update|Синхронный (онлайн)|При выдаче кредита Core создаёт ссудный счёт и передаёт параметры (сумма, ставка, срок) в кредитную систему. Loans проверяет лимит и подтверждает выдачу.|
|FU Core, RB Core|FU DWH, RB DWH|Счёт, Договор, Транзакция (остатки, движения)|Read (batch)|Batch (ежедневно, каждые 15 мин)|DWH строится на выгрузках из АБС для отчётности. Batch-режим не нагружает операционные системы.|
|FU Cards, RB Cards|FU DWH, RB DWH|Карта, Транзакция (карточные операции)|Read (batch)|Batch (ежедневно)|Карточные операции выгружаются из процессинга в DWH для анализа расходов, комиссий и фрод-мониторинга.|
|FU Loans, RB Loans|FU DWH, RB DWH|Кредит, График платежей, Просрочка|Read (batch)|Batch (ежедневно)|Кредитные данные выгружаются в DWH для расчёта кредитного риска, резервов и отчётности.|
|FU Core, FU Cards, FU CRM, FU Loans|FU Data Lake|Транзакция (сырые), События (логи), Документы (скан паспорта), Кредитная история|Create|Streaming (Kafka) + Batch (ежедневно)|Data Lake хранит сырые данные для ML-моделей (фрод, скоринг) и долгосрочного хранения. Streaming — для событий, Batch — для документов.|
|FU Data Lake|Fed DWH|Исторические транзакции (старше 3 лет), исторические кредитные данные|Read/Enrich|Batch (еженедельно)|Исторические данные из Data Lake обогащают отчётность Fed DWH (формы ЦБ за 5 лет).|
|FU Core, RB Core|ESB|Договор, Счёт (события создания/изменения)|Create/Update|Асинхронный (Kafka)|События об изменении договоров и счетов отправляются в ESB для синхронизации с Fed DWH.|
|FU Loans, RB Loans|ESB|Кредитный договор, Лимит, График платежей, Просрочка|Create/Update|Асинхронный (Kafka)|События об изменении кредитных договоров синхронизируются с MDM (лимиты влияют на сегмент клиента) и Fed DWH (витрины кредитного риска).|
|ESB|MDM|Клиент (данные для матчинга и дедубликации)|Create/Update|Асинхронный (Kafka)|ESB передаёт клиентские данные в MDM для глубокого матчинга. Подтверждает или объединяет pre-golden\_id, созданный синхронным потоком.|
|MDM|ESB|Клиент (золотая запись, golden\_id, статус дубля), Продукт (справочник), Сегмент (справочник)|Enrich/Read|Асинхронный (Kafka)|MDM возвращает финальный golden\_id и маппинг дублей в ESB для распространения в CRM и другие системы.|
|MDM|FU CRM, RB CRM|Клиент (золотой ID, маппинг дублей)|Update|Асинхронный (Kafka)|MDM обновляет CRM: проставляет финальный golden\_id, помечает дубли.|
|ESB|Fed DWH|Клиент (golden\_id), Договор, Счёт, Кредит (обогащённые)|Enrich/Create|Асинхронный (Kafka)|ESB передаёт в Fed DWH данные, обогащённые golden\_id, для построения витрин отчётности.|
|FU DWH, RB DWH|Fed DWH|Все сущности: Клиент, Счёт, Договор, Карта, Транзакция, Кредит|Read/Validate/Aggregate|Batch (ежедневно)|Fed DWH консолидирует данные из двух DWH для единой отчётности. Выполняется валидация и агрегация.|
|Fed DWH|BI (единая отчётность)|Витрины данных (агрегированные)|Read/Aggregate|Синхронный (SQL-запрос)|BI строит дашборды и отчёты на основе витрин Fed DWH.|
|Fed DWH|Регулятор (ЦБ РФ)|Формы ЦБ, МСФО-отчётность|Read/Validate|Batch (ежемесячно, ежеквартально)|Регуляторная отчётность формируется на основе Fed DWH с валидацией перед отправкой.|
|MDM|DataHub|Метаданные: схемы клиентов, продуктов, сегментов; владельцы; правила матчинга|Metadata (Collect)|Асинхронный (Kafka + batch)|DataHub фиксирует структуру мастер-данных для поиска и lineage.|
|Fed DWH|DataHub|Метаданные: витрины, lineage, SQL-запросы|Metadata (Collect)|Асинхронный (Kafka + batch)|DataHub отслеживает происхождение данных в отчётности.|
|ESB|DataHub|Метаданные: маршруты, трансформации, схемы сообщений|Metadata (Collect)|Асинхронный (Kafka + batch)|DataHub фиксирует потоки данных между системами.|
|DataHub|Data Office, Аналитики|Lineage, владельцы, описания таблиц|Read|Синхронный (UI/API)|DataHub предоставляет единый интерфейс для поиска данных и понимания их происхождения.|
