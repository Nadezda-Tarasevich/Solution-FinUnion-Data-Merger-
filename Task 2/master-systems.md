### Матрица мастер-систем бизнес-сущностей компании FinUnion Group: промежуточное и целевое состояния

|Сущность|Источник As-Is|Мастер-система (3 месяца)|Целевая мастер-система|Связь с BIAN|Обоснование|
|:-:|:-:|:-:|:-:|:-:|:-:|
|Клиент (Customer)|FU CRM, RB CRM, FU Core, RB Core|MDM (Customer Hub) — золотая запись клиента на основе FU CRM с дополнением из RB CRM|MDM (Customer Hub) — единый источник правды для всех систем|Party Reference Data Directory|FU CRM — операционная система с наибольшим объёмом актуальных данных. MDM строится на её основе с матчингом записей из RB CRM. Целевое состояние — MDM как единственный источник для синхронизации во все системы (FU CRM, RB CRM, FU Core, RB Core).|
|Договор (Agreement)|FU Core, RB Core, FU CRM, RB CRM|FU Core (для новых договоров) + ESB (для синхронизации существующих из RB Core)|FU Core (единая АБС)|Product Access|FU Core — более современная и гибкая АБС. Договоры RB Core мигрируются поэтапно через ESB. На 3 месяца — FU Core как мастер для новых договоров, RB Core — как источник для существующих (с синхронизацией). На 12 месяцев — все договоры в FU Core.|
|Счёт (Account)|FU Core, RB Core|FU Core (для новых счетов) + ESB (для синхронизации остатков из RB Core)|FU Core (единая АБС)|Current Account / Savings Account / Loan Account|Аналогично договорам. Счета физически находятся в двух АБС. На 3 месяца — FU Core мастер для новых, RB Core — источник для существующих с синхронизацией остатков. Цель — полная миграция в FU Core к 12 месяцам.|
|Карта (Card)|FU Cards, RB Cards|FU Cards (для новых карт) + синхронизация статусов из RB Cards|FU Cards (единый карточный процессинг)|Card Management|FU Cards — более современный процессинг. Карты RB Cards не мигрируются физически, а перевыпускаются в FU Cards по истечении срока. Статусы синхронизируются через ESB.|
|Транзакция (Transaction)|FU Core, RB Core, FU Cards, RB Cards|Fed DWH (единая витрина транзакций)|Data Lakehouse + Fed DWH (витрины для отчётности)|Transaction Authorization + Transaction Clearing + Transaction Settlement|Транзакции не имеют единой мастер-системы — они всегда рождаются в операционных системах. Мастером является слой аналитики (Fed DWH → Data Lakehouse), где данные очищаются, дедублицируются и становятся единым источником для отчётности.|
|Платёж (Payment)|FU Core, RB Core (РКО), FU Cards|FU Core (единый платёжный шлюз) + ESB (для синхронизации из RB Core)|FU Core (единый платёжный шлюз)|Payment Execution|Платёжные инструкции должны обрабатываться через единый шлюз для контроля ликвидности и AML. RB Core подключается к шлюзу FU Core через ESB. Цель — полный перевод РКО на FU Core.|
|Продукт (Product)|FU Core (справочник), RB Core (справочник)|MDM (единый справочник продуктов на основе FU Core)|MDM (единый справочник продуктов)|Product Catalog + Product Design|Справочники продуктов — классический случай для MDM. На 3 месяца — маппинг продуктов FU и RB, создание единого справочника. На 12 месяцев — MDM как единственный источник для всех систем.|
|Кредит (Loan)|FU Loans, RB Loans|FU Loans (для новых кредитов) + ESB (для синхронизации существующих из RB Loans)|FU Loans (единая кредитная система)|Credit Risk Management|FU Loans — более современная кредитная система. Кредитные договоры RB Loans мигрируются поэтапно через ESB. На 3 месяца — FU Loans как мастер для новых кредитов, RB Loans — как источник для существующих. Цель — полная миграция в FU Loans к 12 месяцам.|
|Обращение (Interaction)|FU CRM, RB CRM|FU CRM (единая CRM) + ESB (для синхронизации исторических обращений из RB CRM)|FU CRM (единая CRM)|Customer Relationship Management|FU CRM выбрана как база для единой CRM. Обращения из RB CRM синхронизируются через ESB. Цель — полное отключение RB CRM к 12 месяцам.|
|Сегмент клиента (Segment)|FU CRM, RB CRM, FU DWH|MDM (единый справочник сегментов) + FU DWH (правила расчёта)|MDM (справочник) + Data Lakehouse (расчёт сегментов)|Segment Management|Справочник сегментов — в MDM. Правила расчёта сегментов — в аналитическом слое (Data Lakehouse). На 3 месяца — базовый маппинг сегментов FU и RB.|
|Сотрудник (Employee)|FU CRM (справочник), RB CRM, HR-система (AD)|HR-система (Active Directory) — единый справочник сотрудников|HR-система (Active Directory) + IAM (управление доступом)|Employee Management (расширение BIAN)|Сотрудники — корпоративные учётные записи. Мастер-система — HR-система (Active Directory). FU CRM и RB CRM получают данные сотрудников через LDAP.|
|Каталог данных (Data Catalog)|Нет (ни в FU, ни в RB)|DataHub (начальный сбор метаданных из Fed DWH, MDM, ESB)|DataHub (полный каталог: lineage, владельцы, схемы, качество)|Data Governance (расширение BIAN)|Каталог данных — новый компонент. На 3 месяца — сбор метаданных из ключевых систем (Fed DWH, MDM, ESB). На 12 месяцев — полный lineage от CDC до BI, фиксация владельцев данных, автоматическая проверка качества.|
