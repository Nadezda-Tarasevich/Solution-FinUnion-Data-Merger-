### Инкрементальный план миграции FinUnion + RetailBank (12 месяцев)



###### План миграции

|Этап|месяцы|Содержание|Результат|
|:-:|-|:-:|:-:|
|1. Data Discovery|1|1. Инвентаризация систем: FU Core, RB Core, FU CRM, RB CRM, FU Cards, RB Cards, FU Loans, RB Loans, FU DWH, RB DWH, FU BI, RB BI, FU ESB, RB P2P. <br />2. Определение сущностей: Клиент, Счёт, Договор, Карта, Транзакция, Платёж, Продукт, Обращение, Сегмент. <br />3. Составление карты потоков данных (Data Flow Diagram As-Is). <br />4. Фиксация владельцев данных (Data Owners) по каждой сущности. <br />5. Выявление проблем качества: дубли клиентов, разные справочники, форматы дат, статусов.|Реестр данных (Data Inventory) — полный перечень систем, таблиц, потоков, владельцев и проблем качества|
|2. MDM и маппинг справочников|1-3|1. Развёртывание MDM (Customer Hub) на PostgreSQL. <br />2. Загрузка клиентов FU CRM и RB CRM в MDM. <br />3. Разработка правил матчинга: ИНН (для юрлиц), паспорт + ФИО + дата рождения (для физлиц). <br />4. Дедубликация клиентов: автоматическое объединение дублей, ручная верификация спорных случаев. <br />5. Маппинг справочников: продукты (FU vs RB), типы счетов, статусы договоров, валюты, отделения. <br />6. Создание единого справочника продуктов в MDM.|MDM запущен — 100% клиентов имеют golden\_id. Единые справочники — продукты, типы, статусы, валюты. Коэффициент дублирования клиентов — менее 1%|
|3. Fed DWH и единая отчётность|2-4|1. Развёртывание Fed DWH на ClickHouse. <br />2. Настройка batch-выгрузок из FU DWH и RB DWH в Fed DWH (Airflow DAG, ежедневно, 02:00). <br />3. Маппинг справочников в ETL-процессе (использование единых кодов из MDM). <br />4. Создание витрин: форма ЦБ , управленческая отчётность. <br />5. Валидация: ежедневная сверка остатков (Fed DWH vs FU Core + RB Core). <br />6. Настройка BI (Superset/Tableau) для единой отчётности.|Fed DWH работает — все формы ЦБ и управленческая отчётность строятся на Fed DWH. Сходимость остатков — расхождения менее 0.01%. BI — единые дашборды для аналитиков|
|4. Миграция клиентов и обращений|3-6|1. Миграция всех клиентов (физ. лица + юр. лица) из RB CRM в FU CRM через CDC (Debezium) + batch. <br />2. Присвоение golden\_id новым клиентам через MDM. <br />3. Миграция обращений (3 года) из RB CRM в FU CRM. <br />4. Дедубликация обращений по golden\_id + теме + дате. 5. Переключение контакт-центра на единую CRM (FU CRM). 6. Отключение RB CRM (10 месяц).|Единая CRM — все клиенты и обращения в FU CRM. RB CRM отключена — 0 активных сессий|
|5. Миграция счетов, договоров и кредитов|3-10|1. Миграция активных счетов и договоров из RB Core в FU Core через ESB (поэтапно: сначала закрытые, потом активные). 2. Миграция исторических транзакций (3-7 лет) из RB Core + RB DWH в Data Lakehouse (Iceberg на S3). 3. Миграция кредитных договоров из RB Loans в FU Loans (с проверкой остатков). 4. Переключение новых договоров: создание только в FU Core. 5. Валидация: ежедневная сверка остатков (FU Core vs RB Core до отключения). 6. Отключение RB Core и RB Loans (12 месяц).|Единая АБС — все счета и договоры в FU Core. Единая кредитная система — FU Loans. RB Core + RB Loans отключены — 0 запросов|
|6. Миграция карт и завершение|3-12|1. Перевыпуск карт RB Cards в FU Cards по истечении срока (3-12 месяц). <br />2. Принудительный перевыпуск при блокировке/утере. <br />3. Миграция карточных транзакций (история) в Data Lakehouse. <br />4. Переключение всех интеграций на единую платформу (ESB + Kafka + API Gateway). <br />5. Отключение RB Cards (12 месяц). <br />6. Финальная верификация: все системы RetailBank отключены, отчётность строится на единой платформе, все клиенты в MDM.|Единый карточный процессинг — FU Cards. RB Cards отключён. Все интеграции — через ESB + Kafka. DataHub — 100% lineage. Проект завершён|

###### Критерии завершения каждого этапа

|Этап|Критерий|Метод проверки|
|:-:|:-:|:-:|

|2. MDM|100% клиентов имеют golden\_id. Доля дублей < 1%|SQL-запрос к MDM|
|3. Fed DWH|Формы ЦБ сдаются из Fed DWH. Расхождения остатков < 0.01%|Сверка за 3 дня подряд|
|4. Миграция клиентов|RB CRM отключена. 0 запросов к RB CRM|Мониторинг (30 дней)|
|5. Миграция счетов|RB Core + RB Loans отключены. 0 запросов|Мониторинг (30 дней)|
|6. Миграция карт|RB Cards отключён. Все интеграции через ESB + Kafka|Инвентаризация интеграций|
