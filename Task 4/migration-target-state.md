### Образ целевого результата: FinUnion Group через 12 месяцев





###### Какие системы остаются



|Система|Изменения|Обоснование|
|:-:|:-:|:-:|
|FU Core (АБС)|Расширена: принимает данные из RB Core, стала единой АБС для всей группы|FU Core — более современная АБС. RetailBank отключается|
|FU CRM|Расширена: принимает обращения из RB CRM, стала единой CRM|FU CRM выбрана как база для единой CRM|
|FU Cards|Расширен: принимает карты из RB Cards (перевыпуск), стал единым процессингом|FU Cards — современный процессинг, соответствующий PCI DSS|
|FU Loans|Расширена: принимает кредитные договоры из RB Loans, стала единой кредитной системой|FU Loans — единая система для всех кредитных продуктов|
|FU DWH|Превращён в источник для Fed DWH. Хранит исторические данные FU|Исторические данные не удаляются, но вся новая отчётность строится на Fed DWH|
|FU ESB|Расширен: добавлены Kafka (события) и API Gateway (входной слой)|ESB становится частью единой интеграционной платформы|



###### Какие системы выводятся из эксплуатации

|Система|Что происходит с данными|Причина вывода|
|:-:|:-:|:-:|
|RB Core (АБС)|Все счета, договоры и транзакции мигрированы в FU Core. RB Core отключается|Две АБС — дорого и сложно. FU Core — стратегическая платформа|
|RB CRM|Все обращения, клиенты и заявки мигрированы в FU CRM. RB CRM отключается|Единая CRM снижает стоимость поддержки и упрощает интеграцию|
|RB Cards|Карты RB Cards не мигрируются физически. По истечении срока карты перевыпускаются в FU Cards. После последней карты — RB Cards отключается|Единый карточный процессинг снижает стоимость и упрощает соответствие PCI DSS|
|RB Loans|Все кредитные договоры мигрированы в FU Loans. RB Loans отключается|Единая кредитная система для всех продуктов|
|RB DWH|Все исторические витрины мигрированы в Fed DWH. RB DWH отключается|Единое хранилище отчётности устраняет расхождения между отчётами FU и RB|
|RB BI|Все дашборды и отчёты перенесены в единый BI (Superset/Tableau). RB BI отключается|Единая BI исключает дублирование отчётов и метрик|
|RB P2P (Point-to-Point)|Все точечные интеграции RB заменены на ESB + Kafka. P2P отключается|Централизованная шина снижает сложность поддержки интеграций|



###### Какие данные мигрируются

|Данные|Откуда|Куда|
|:-:|:-:|:-:|
|Клиенты (физические лица)|RB CRM|FU CRM + MDM|
|Клиенты (юридические лица / ИП)|RB CRM|FU CRM + MDM|
|Договоры (кредитные, карточные, ДБО)|RB Core|FU Core|
|Счета (расчётные, ссудные, вкладные)|RB Core|FU Core|
|Транзакции (3-7 лет)|RB Core + RB DWH|Data Lakehouse (Iceberg)|
|Карты (активные)|RB Cards|FU Cards (перевыпуск)|
|Кредитные договоры|RB Loans|FU Loans|
|Обращения (3 года)|RB CRM|FU CRM|
|Исторические витрины (для ЦБ, МСФО)|RB DWH|Fed DWH (ClickHouse)|
|Справочники (продукты, тарифы, отделения)|RB Core, RB CRM|MDM|



###### Какие потоки переключаются

|Поток|Было (As-Is)|Стало (To-Be)|
|:-:|:-:|:-:|
|Клиент → CRM|Клиент → RB CRM (отдельно)|Клиент → API Gateway → FU CRM (единая точка входа)|
|Сотрудник → CRM|Сотрудник → RB CRM (отдельно)|Сотрудник → API Gateway → FU CRM (единая CRM)|
|CRM → Core (договоры, счета)|RB CRM → RB Core (P2P)|RB CRM (через ESB) → FU Core|
|Core → Cards (выпуск карт)|RB Core → RB Cards (P2P)|FU Core → FU Cards (единый процессинг)|
|Core → Loans (кредиты)|RB Core → RB Loans (P2P)|FU Core → FU Loans (единая кредитная система)|
|Операционные системы → DWH|RB Core → RB DWH (batch)|FU Core → Fed DWH (через Lakehouse, ELT)|
|DWH → BI|RB DWH → RB BI (отчёты)|Fed DWH + Lakehouse → BI (единая аналитика)|
|DWH → Регулятор|RB DWH → ЦБ РФ (отдельно)|Fed DWH → ЦБ РФ (единая отчётность)|
|Отчётность по кредитам|RB Loans → RB BI|FU Loans → Lakehouse → DWH → BI|



##### Критерии подтверждения завершения перехода

###### Системные критерии (обязательные)

|Критерий|Целевое значение|
|:-:|:-:|
|RB Core отключена|0 активных запросов к RB Core. Все данные мигрированы в FU Core|
|RB CRM отключена|0 активных сессий в RB CRM. Все обращения мигрированы в FU CRM|
|RB Cards отключён|0 активных карт в RB Cards. Все карты перевыпущены в FU Cards|
|RB Loans отключена|0 активных кредитов в RB Loans. Все договоры мигрированы в FU Loans|
|RB DWH отключена|0 запросов к RB DWH. Все отчёты строятся на Fed DWH|
|RB BI отключена|0 дашбордов в RB BI. Все дашборды перенесены в единый BI|
|RB P2P отключена|0 активных P2P-интеграций. Все потоки переключены на ESB + Kafka|

###### Критерии качества данных

|Критерий|Целевое значение|
|:-:|:-:|
|MDM: доля клиентов с golden\_id|100% клиентов FU + RB имеют golden\_id|
|MDM: дедубликация клиентов|Менее 1% дублей после матчинга|
|Fed DWH: сходимость балансов|Остатки в Fed DWH = Остатки в FU Core (с точностью до 0.01 руб.)|
|Fed DWH: полнота транзакций|Количество транзакций в Fed DWH = Количество транзакций в FU Core + RB Core (за период)|
|Data Lakehouse: полнота событий|99.9% событий из Kafka записаны в Iceberg-таблицы|
|Data Lakehouse: сходимость с DWH|Агрегированные витрины в DWH = агрегация сырых данных в Lakehouse|

###### Бизнес-критерии

|Критерий|Целевое значение|
|:-:|:-:|
|Единый клиентский профиль|100% клиентов имеют единый профиль (Customer 360) в MDM|
|Единая отчётность (ЦБ)|Все формы ЦБ (0409101, 0409155, МСФО) сдаются из Fed DWH|
|Единая управленческая отчётность|Все дашборды BI отображают данные по всей группе (FU + RB)|
|Снижение ручных сверок|Количество ручных сверок между FU и RB = 0|
|Срок сдачи отчётности (ЦБ)|Не более 1 часа после закрытия месяца (ранее — 2-3 дня)|

###### Технические критерии

|Критерий|Целевое значение|
|:-:|:-:|
|ESB + Kafka: доступность|99.99% (не более 52 минут простоя в год)|
|Fed DWH: время ответа|90% запросов BI — менее 10 секунд|
|CDC: задержка|95% событий — менее 3 секунд от записи в Core до публикации в Kafka|
|Data Lakehouse: задержка|95% событий — менее 5 минут от Kafka до Iceberg|
|Airflow: успешность DAG|99% DAG завершаются без ошибок|
|DataHub: полнота lineage|100% таблиц в Fed DWH имеют lineage (от источника до витрины)|
